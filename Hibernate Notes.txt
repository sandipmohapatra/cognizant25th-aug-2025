Hibernate
-------------------------
1) Hibernate is a object Relational Mapping tool.
2) Hibernate is used to store the objects into a database where as JDBC store primitive types in a database.
3) It provides connection pooling.
4) It provides two types of caching.
5) We do not need to write most of the sql scripts for insert, delete object and selecting the result set.
6) Hibernate is database independent code will work for oracle, MySql, SqlServer etc.
 7) As hibernate is set of objects we need not to learn sql languages .we treat table as object.
8) Basic sql queries are generated by hibernate.
9) We need not do query tuning in case of hibernate.
10) Development and maintenance is very easy because we need not to write queries.

Generator classes
---------------------------------------------------------------------------------
It is used to generate identifier column values. The first is generally called identifier column.
The different generator classes are:-
1)sequence:- The database sequence is automatically generated.
2)Assigned :-get value from application
3)User defined generator class:-
4)UUID :-It uses 128bit UUID algorithm to generate identifiers of type string, unique within a network .
5)GUID:-It is a database generated string on oracle, MySql, Sql server.
6)Identity:-Mysql takes identity, oracle takes sequence.
7)foreign:- used in relationship primary key.
8)hilo:-hilo use hilo algorithm to efficiently generate identifiers of type long, sort, int given in a table and column only for a particular database. 
9)sequence-hilo:-same as hilo algorithm but it is for a given named Database sequence.
10)Native:-It picks identity, sequence or hilo depending upon the capabilities of the underlying database.
*oracle do not support identity, Mysql support .Oracle support sequence
11)Select:- Retrieves primary key assigned by database trigger by selecting the row by some unique key and retrieving the primary key value.
12)Increment:- it increments as sequence.

1. @OneToOne
This defines a one‑to‑one relationship between two entities.
Example:

One User ↔ One Address
One Employee ↔ One Passport

Only one row in one table is linked to one row in another table.

2. cascade = CascadeType.ALL
Cascade means:

Whatever operation happens on the parent will also happen on the child.

CascadeType.ALL includes:

PERSIST → save child when parent is saved
MERGE → update child when parent is updated
REMOVE → delete child when parent is deleted
REFRESH → refresh child
DETACH → detach child

So if you delete the parent → the child is automatically deleted too.

@ManyToOne
@JsonBackReference
@JoinColumn(name = "customer_id")
private Customer customer;

@ManyToOne
This field is the many-side of a Customer ↔ Order type relation: many orders belong to one customer.


@JoinColumn(name = "customer_id")
Places a foreign key column (customer_id) in the owning table (e.g., orders table). That column points to customers.id.


@JsonBackReference
Jackson annotation that marks this as the back (child→parent) side of a bidirectional relationship to prevent infinite recursion during JSON serialization.
Pair it with @JsonManagedReference on the parent (Customer) side.
------------------------------------------------------------------------------------------------------------------------
What @JsonBackReference Does
@JsonBackReference is a Jackson annotation that helps avoid infinite recursion during JSON serialization when you have bidirectional relationships (e.g., parent ↔ child).

It marks the “back” part of the relationship (the child → parent link).
Jackson will serialize the forward side (annotated with @JsonManagedReference)
and skip the back side to prevent cycles.
It still works for deserialization: Jackson can populate both sides from JSON that includes the managed side.

Think of it as:

@JsonManagedReference → serialize this side (parent → children).
@JsonBackReference → do not serialize this side (child → parent).

1️⃣ @ManyToOne
Defines the many → one side of the relationship.
Examples:

Many Orders → One Customer
Many Employees → One Department
Many Students → One College

This annotation is always placed on the child side.

2️⃣ fetch = FetchType.LAZY
💡 What it means:
The parent entity will NOT be loaded automatically when loading the child.
Example:
JavaOrder order = orderRepository.findById(1L).get();

Hibernate loads Order object immediately.
It loads Customer only when you call:
Javaorder.getCustomer();  // triggers lazy loadingShow more lines


⚠️ Why LAZY is recommended:

Improves performance
Reduces unnecessary SQL joins
Avoids loading large parent objects automatically

Historically, ManyToOne default fetch type = EAGER,
but best practice today = LAZY.

3️⃣ optional = false
💡 What it means:
This relationship is mandatory.
The child must have a parent.
Equivalent DB constraint:
SQLcustomer_id NOT NULLShow more lines
What JPA/Hibernate enforces:

Cannot save the child without setting the parent
Hibernate may throw:
PropertyValueException: not-null property references a null

This is used when the foreign key should never be null.

@ManyToOne(fetch = FetchType.LAZY, optional = false)
